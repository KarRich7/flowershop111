# «Цветы Урала» — интернет-магазин цветов

> **Владельцу:** простая памятка — вход в админку, обновление, настройки, боты, резервные

Сайт + админ-панель + Telegram-бот + ВК-бот на **одном сервере и одной базе данных**
(модульный монолит). При первом запуске база заполняется демо-товарами и демо-заказами
(`is_demo=true`, удаляются командой `clear_demo`); на своём компьютере оплата — тестовый
симулятор, на боевом сервере — RollyPay (СБП, карта) или оплата при получении ([docs/DEPLOY.md](docs/DEPLOY.md)). Покупатель может оформить
заказ без регистрации или войти через Telegram / ВКонтакте — тогда статусы приходят в
мессенджер, а контакты и адрес запоминаются.

> Название, логотип, адрес, телефон, график работы и фирменные цвета меняются в
> админке: **Настройки → Магазин** (без правки кода, только владелец).

| Компонент | Технологии |
|---|---|
| Сайт и админ-панель | Next.js 15 (App Router) + TypeScript, без UI-фреймворков |
| Сервер | Python 3.13, Django 5.2, Django REST Framework 3.18, drf-spectacular (OpenAPI) |
| База данных | PostgreSQL 16 (миграции Django, суммы в копейках) |
| Фоновые задачи | Redis 7 + Celery (worker + beat) |
| Telegram | aiogram 3 — обычный чат-бот (inline-кнопки), без Mini App / Web App |
| ВКонтакте | VK Bots Long Poll API + messages.send — сообщения сообщества |
| Запуск | Docker Compose |

## Быстрый старт (Docker Compose)

```bash
cp .env.example .env          # при необходимости поменяйте секреты и токены
docker compose up -d --build  # первый запуск: миграции + демо-данные автоматически
```

| Адрес | Что там |
|---|---|
| http://localhost:3000 | Сайт магазина |
| http://localhost:3000/admin | Админ-панель (вход владельца и сотрудников); на сайте ссылки на неё нет |
| http://localhost:3000/account | Личный кабинет покупателя (вход через Telegram / ВК) |
| http://localhost:8000/api/docs/ | Swagger UI (OpenAPI 3) — только на тестовом стенде |
| http://localhost:8000/django-admin/ | Технический Django admin — только на тестовом стенде |

Сервисы compose: `db`, `redis`, `backend` (gunicorn; миграции и `seed_demo --if-empty`
при старте), `celery-worker`, `celery-beat`, `frontend`, `telegram-bot`, `vk-bot`, `db-backup`.
Данные PostgreSQL, Redis и загруженные фото лежат в именованных томах и **сохраняются
между перезапусками** (`docker compose down` их не удаляет; `down -v` — удаляет).

Полезные команды:

```bash
docker compose logs -f backend celery-worker             # логи
docker compose exec backend python manage.py seed_demo --reset   # пересоздать демо-данные
docker compose exec backend python manage.py changepassword owner   # новый пароль владельца
docker compose exec backend python manage.py clear_demo --yes     # удалить демо-заказы и демо-покупателей
docker compose exec backend python manage.py security_check      # проверка настроек безопасности
docker compose run --rm backend python -m pytest         # тесты бэкенда (нужна БД из compose)
docker compose exec db-backup /bin/sh /backup.sh         # внеплановая резервная копия → ./backups
```

### Вход в админку и сотрудники

В базе одна учётная запись — **владелец** `owner` / `owner12345` (демо-логины флориста и курьеров
удалены). При первом входе сайт попросит сменить пароль: **Админка → «Сменить пароль»**
(от 10 символов). Свой логин и пароль владельца для новой базы можно задать заранее в `.env`:
`OWNER_USERNAME`, `OWNER_PASSWORD`.

Сотрудников заводит только владелец: **Админка → Сотрудники → «+ Сотрудник»** → логин, имя,
телефон, роль, пароль (от 10 символов; сообщите его сотруднику лично).

| Роль | Что доступно |
|---|---|
| Владелец | всё: цены, настройки, сотрудники, статистика, возвраты, журнал |
| Флорист | товары, склад, сборка, подтверждение заказов, продажа в магазине |
| Курьер | только назначенные ему доставки и их статусы |

* Сменить пароль сотруднику — нажать на него в списке → «Новый пароль» → «Сохранить».
* Закрыть доступ — снять «Доступ активен» или «Удалить» (его доставки вернутся в «без курьера»).
* Забыли пароль владельца: `docker compose exec backend python manage.py changepassword owner`.
* Можно быть в админке одновременно с телефона и компьютера; «Выйти» — выход только на этом устройстве,
  смена пароля — выход на всех остальных.
* 5 неверных паролей подряд блокируют вход под этим логином на 15 минут.

Пароли хранятся только в виде хешей (PBKDF2). Подробно о защите — [docs/SECURITY.md](docs/SECURITY.md).

### Проверка с телефона

Телефон и компьютер — в одной Wi-Fi сети. В `.env` добавьте `SITE_BIND=0.0.0.0`, выполните
`docker compose up -d frontend` и откройте на телефоне `http://<IP компьютера>:3000`
(IP: `ipconfig` в Windows → «IPv4-адрес»). Windows может спросить разрешение для Docker в
брандмауэре — разрешите для частной сети.

### Карта зон доставки (Яндекс)

Мастерская — в Кондратово (ЖК «Медовый», Пермский край). Зоны доставки — многоугольники на карте:
Кондратово и ЖК «Медовый» (150 ₽, бесплатно от 1 500 ₽), районы Перми и пригород до 12 км (демо-границы
из OpenStreetMap); их стоимость, порог бесплатной доставки и сами
границы меняются в админке: **Настройки → Доставка → Районы доставки** (там же районы добавляются и удаляются). Адрес вне всех зон оформить нельзя,
номер дома проверяется геокодером.

1. Войдите на <https://developer.tech.yandex.ru> → «Подключить API» → **«JavaScript API и
   HTTP Геокодер»** (бесплатного тарифа хватает для MVP).
2. В настройках ключа укажите домен сайта (HTTP Referer), например `cvety-urala.ru`, и `localhost`.
3. Пропишите `YANDEX_MAPS_API_KEY=...` в `.env` → `docker compose up -d --force-recreate backend frontend`
   (простой `restart` не перечитывает `.env`).

Проверить ключ: **Настройки → Система → «Карта и поиск адресов» → «Проверить ключ Яндекса»** или
`docker compose exec backend python manage.py check_maps` — видно, принят ли ключ картой и HTTP Геокодером.
Если карта работает, а геокодер отвечает `403 Invalid api key`: ключ ещё активируется (до 15 минут),
выпущен не для «JavaScript API и HTTP Геокодер», или в нём включено ограничение по HTTP Referer/IP —
запросы сервера его не проходят. Тогда выпустите второй ключ без ограничений и укажите его в
`YANDEX_GEOCODER_API_KEY` (карта продолжит работать с `YANDEX_MAPS_API_KEY`). Пока Яндекс
отклоняет запросы, адреса проверяются через OpenStreetMap (Nominatim) — сайт работает.

Без ключа карта Яндекса открывается в ограниченном тестовом режиме, а адреса проверяются
через Nominatim (OpenStreetMap) — для теста этого достаточно, для запуска ключ обязателен. Подробнее — [docs/ENV.md](docs/ENV.md).

### Как вручить: адрес у получателя, сюрприз, анонимно, фото до отправки

При оформлении доставки «Другому человеку» покупатель может отметить:
* **«Не знаю адрес — узнайте у получателя»** — вместо карты выбирается район / населённый пункт
  (цена доставки по нему). Флорист видит в заказе телефон получателя и форму адреса; пока адрес
  не вписан, заказ не подтвердить. Оплата онлайн — после этого звонка.
* **«Сюрприз: не звонить заранее»** и **«Не говорить, от кого букет»** — отметки видят флорист и курьер.
* **«Прислать фото букета перед отправкой»** (включено по умолчанию) — флорист загружает фото в
  карточке заказа, покупатель видит его на странице заказа и получает сообщение в Telegram/ВК.
  Без фото заказ не передать курьеру.

Гостевые заказы запоминаются на устройстве покупателя — их видно на странице «Мой заказ».

### Два режима конструктора

Вверху страницы `/constructor` — переключатель:

* **«С эскизом»** (`/constructor`) — покупатель сам расставляет цветы на эскизе (подробно ниже).
* **«По фото»** (`/constructor?mode=photo`) — без эскиза: покупатель по фотографиям выбирает
  только **цветы** (количество каждого), **бумагу/упаковку** и **ленту**, а форму, высоту и
  расстановку флорист делает **на своё усмотрение**. Цена считается сервером так же, как в
  эскизном режиме. В корзине, на странице заказа и в админке такой букет показывается
  фотографиями выбранных цветов с пометкой «Оформит флорист» (в составе заказа —
  `florist_choice: true`, эскиза нет).

**Не больше 30 цветков в букете** (зелень не считается) — в обоих режимах: кнопки «Добавить»
становятся неактивными, появляется подсказка; сервер тоже не примет больше
(`too_many_stems`). Владелец может уменьшить лимит в **Настройки → Заказы и оплата**, но не
поднять выше 30 (миграция переводит старое значение 101 в 30).

### Конструктор из настоящих цветов

Кнопка «+» ставит цветок в общую плотную «шапку» (по золотой спирали от центра, остальные
чуть раздвигаются, ничего не свисает за упаковку); перетащенный вручную цветок остаётся там,
где его отпустили, — авто-раскладка его обходит. «Расставить» перемешивает сорта равномерно.

В конструкторе букет собирается из фотографий: цветы и зелень — вырезанные головки и
веточки. Выбранный цветок можно отразить и повернуть (кнопки над ним или клавиши F, [ и ]),
убрать — кнопкой или вынести за букет. Упаковка рисуется по материалу: бумага (несколько
листов с загибами и фактурой), прозрачная плёнка, фетр, шляпная коробка; есть вариант
**«Без упаковки»** — стебли перевязаны лентой.

**Объёмная лента.** Бант, перевязка и обмотка стеблей строятся как настоящие 3D-поверхности
(петли с изнанкой и складками у узла, закрученные хвосты с косым срезом или «ласточкиным
хвостом», узелок) и освещаются по материалу: атлас блестит полосами вдоль нитей, шёлк мягче и
струится, органза полупрозрачная, джутовый шпагат — витой жгут с распушёнными кончиками. Цвет
берётся из карточки ленты. Картинку отдаёт сам фронтенд (`/ribbon/<ключ>.png`, рендер без
внешних библиотек, кешируется), поэтому эскиз одинаковый в конструкторе, корзине и заказе.

**«В вазе».** Переключатель над эскизом показывает, как букет будет стоять в стеклянной вазе:
упаковка снята, стебли перевязаны и уходят в воду (с преломлением), видны блики стекла, толстое
дно и тень на столе. Формы — «Цилиндр», «Шар», «Конус»; для цилиндра, если в магазине есть
доп. товар «Ваза…», его можно сразу добавить в корзину. Для шляпной коробки режим недоступен.
`d26_dense_bouquets.jpg` (15 и 30 цветков), `d24_constructor_photo.jpg`, `d25_cart_photo_bouquet.jpg`,
`m12_constructor_photo.jpg` («По фото»).

**Свои цветы, упаковка, ленты, открытки.** Флорист или владелец создаёт товар нужного типа
(**Товары → «Новый товар»**) и загружает любое фото цветка: сервер вырезает его
нейросетью IS-Net (ONNX, работает локально), выделяет бутон, а рамку можно поправить мышью.
Модель (~180 МБ) скачивается при сборке Docker-образа; без неё работает простой алгоритм —
для фото на однотонном светлом фоне. Локально без Docker модель можно положить в
`backend/models/isnet-general-use.onnx` (ссылка — в `backend/Dockerfile`).
Демо-фото к цветам из демо-набора подключаются автоматически при старте (`seed_demo --if-empty`).

### Категории, «О нас», склад

* **Категории** букетов и поштучных цветов — раздел «Категории»: создать, переименовать,
  поменять порядок, удалить (товары переносятся в другую категорию), добавить товары.
* **Страница «О нас»** — текст и карусель фото, раздел «Страница „О нас“» (только владелец).
* **Склад** — новые позиции, изменение, удаление/архив, поставки, списания, инвентаризация,
  история с выгрузкой в CSV. Данные о магазине и правила заказов меняет только владелец.
* **Удаление товаров.** Владелец удаляет любой товар навсегда — кнопка «Удалить навсегда» в карточке
  товара: пропадают карточка, фото и строки в корзинах, а в прошлых заказах остаются название, цена и
  эскиз букета. Складская история товара остаётся в архиве склада для отчётов. Если товар есть в
  незавершённом заказе, он сначала только снимается с продажи — удалить можно после выполнения или
  отмены заказа. Флорист удаляет только товары без истории, остальные снимает с продажи.

### Оплата

* На тестовом стенде — **онлайн-оплата через симулятор** (деньги не списываются) и, если
  включено в **Настройки → Заказы и оплата**, оплата при получении.
* В боевом режиме (`PRODUCTION=true`) симулятор выключается сам: пока не подключена касса,
  сайт и боты принимают заказы с **оплатой при получении**.
* **RollyPay** (основной): `PAYMENT_PROVIDER=rollypay`, `ROLLYPAY_API_KEY`, `ROLLYPAY_SIGNING_SECRET`,
  сначала `ROLLYPAY_TEST_MODE=true`; callback_url кассы — `https://<домен>/api/v1/payments/webhook/rollypay`.
  По шагам — [docs/DEPLOY.md](docs/DEPLOY.md#6-оплата-rollypay). Возвраты — вручную в кабинете RollyPay.
* ЮKassa оставлена запасным вариантом (`PAYMENT_PROVIDER=yookassa`, тот же раздел DEPLOY.md).
* `ONLINE_PAYMENTS=on|off|auto` — принудительно включить/выключить онлайн-оплату.

### Подключение настоящих ботов

Пока токенов нет, на сайте **нет кнопок «Войти через Telegram / ВКонтакте»** и уведомлений в
мессенджеры: покупатель оформляет заказ как гость (статус — по ссылке из заказа или на странице
«Мой заказ», имя и телефон подставляются только на том же устройстве). Что подключено, видно в
админке: **Настройки → «Мессенджеры: уведомления и вход покупателей»**. Токены — секреты, их
вписывают только в `.env` на сервере, после чего пересоздают контейнеры:

```bash
docker compose up -d --force-recreate backend celery-worker telegram-bot vk-bot
```

* **Telegram:** создайте бота у @BotFather → `TELEGRAM_BOT_TOKEN=...` и
  `TELEGRAM_BOT_USERNAME=имя_бота` (без @) в `.env` → `docker compose up -d telegram-bot`. Необязательно: `TELEGRAM_STAFF_CHAT_ID` — чат
  сотрудников для уведомлений о новых заказах и запросах «связаться с флористом».
* **ВКонтакте:** в сообществе включите «Сообщения» и «Возможности ботов», создайте ключ
  доступа (права: сообщения, фотографии), включите Long Poll API (тип событий
  «Входящее сообщение») → `VK_GROUP_TOKEN=...`, `VK_GROUP_ID=...` → `docker compose up -d vk-bot`.
* Без токенов контейнеры ботов пишут предупреждение и завершаются с кодом 0 — это
  ожидаемо; кнопки входа через этот мессенджер на сайте при этом не показываются.
  Демо-симулятора ботов на сайте больше нет.
* Кнопки-ссылки на `localhost` Telegram не принимает — для живого теста задайте
  публичный `FRONTEND_URL` (например, через туннель); иначе ссылка придёт текстом.

### Парсер ВК → Telegram-канал

Папка `vk-parser` следит за стеной https://vk.ru/cvetyurala и публикует новые посты в
Telegram-канал. Включается в `.env`: `COMPOSE_PROFILES=parser`, `VK_PARSER_TELEGRAM_BOT_TOKEN`,
`VK_PARSER_TELEGRAM_CHAT_ID`, на сервере ещё `VK_PARSER_VK_TOKEN` (сервисный ключ ВК — чтение
через официальный API) → `docker compose up -d --build`; журнал —
`docker compose logs -f vk-parser`; меню разового сбора — `docker compose run --rm vk-parser menu`
(Windows: `parser-menu.cmd`). Держите его включённым только в одном месте (сервер **или**
компьютер). Подробно — [docs/DEPLOY.md](docs/DEPLOY.md#8-парсер-вк--telegram-канал) и
[vk-parser/README.md](vk-parser/README.md).

### Вход покупателей через Telegram / ВКонтакте

На оформлении заказа, на странице заказа и в `/account` есть кнопки «Войти через Telegram» и
«Войти через ВКонтакте». Как это работает:

1. Сайт открывает чат с ботом по ссылке `t.me/<бот>?start=login_…` (ВК: `vk.me/club<ID>?ref=login_…`).
2. Бот спрашивает «Войти на сайт?» — покупатель нажимает **«Войти»** (или «Это не я»).
   Если ссылка не открылась, достаточно отправить боту 6-значный код с сайта.
3. Сайт запоминает покупателя на 180 дней: имя, телефон, e-mail и прошлый адрес подставляются
   сами, статусы заказов приходят в мессенджер, в кабинете — история заказов и выход.

Нужно: запущенные боты (`telegram-bot`, `vk-bot`) с токенами из раздела выше. Для локальной
проверки без мессенджера — `CUSTOMER_LOGIN_TEST_MODE=true` (появится кнопка «Подтвердить вход
(тестовый режим)»); **в продакшене — `false`**.

### Шрифты и сборка без доступа к Google

Шрифты Cormorant Garamond и Manrope лежат в репозитории (`frontend/app/fonts/*.woff2`,
лицензия SIL OFL — `frontend/app/fonts/OFL.txt`) и подключаются обычным `@font-face`
(`frontend/app/fonts.css`). `npm run build` / `docker compose build` больше не обращается к
fonts.googleapis.com, поэтому не падает с ошибкой `next/font … Cannot read properties of null`
там, где Google Fonts недоступен или отвечает не так, как ждёт загрузчик.

### Обновление уже запущенного стенда

```bash
docker compose up -d --build      # пересборка; миграции применяются при старте backend
docker compose logs -f backend    # проверить, что миграции прошли
```
При обновлении миграция `core.0007` удаляет все учётные записи, кроме владельца (демо-флорист и
демо-курьеры); их доставки остаются без курьера.
Первая сборка backend скачивает модель вырезания (~180 МБ); без интернета на сервере —
`docker compose build --build-arg CUTOUT_MODEL_URL= backend` (будет простой алгоритм).

## Запуск в интернете (домен + HTTPS)

Пошагово — [docs/DEPLOY.md](docs/DEPLOY.md): сервер, домен, `.env` (`PRODUCTION=true`,
`SITE_DOMAIN`, новые секреты), запуск

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```
(Caddy сам получает сертификат Let's Encrypt; снаружи открыты только порты 80/443).

## Локальный запуск без Docker

Требуется Python 3.12+, Node 20+, PostgreSQL 14+, Redis 6+.

```bash
cp .env.example .env           # DJANGO_DEBUG=true удобно для разработки
# База: createuser flowers -P; createdb -O flowers flowers

cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo               # демо-данные (повторный запуск ничего не дублирует)
python manage.py runserver 0.0.0.0:8000
celery -A config worker -B -l info       # в отдельном терминале
python manage.py run_telegram_bot        # при наличии TELEGRAM_BOT_TOKEN
python manage.py run_vk_bot              # при наличии VK_GROUP_TOKEN и VK_GROUP_ID
python manage.py check_bots              # проверка токенов, связи с Telegram (TELEGRAM_PROXY) и сообщества ВК

cd ../frontend
npm ci
npm run dev                               # http://localhost:3000 (API проксируется на :8000)
```

## Резервное копирование

Контейнер `db-backup` делает `pg_dump -Fc` раз в `BACKUP_INTERVAL_HOURS` (по умолчанию 24 ч)
в каталог `./backups` и хранит `BACKUP_KEEP` последних копий. Восстановление:

```bash
docker compose exec -T db pg_restore --clean --if-exists -U flowers -d flowers < backups/<файл>.dump
```
