# ВК через Selenium: меню, постоянное наблюдение и Telegram

> **На сервере вместе с сайтом** парсер запускается через Docker Compose как сервис `vk-parser` — см. [../docs/DEPLOY.md](../docs/DEPLOY.md), раздел 8. Ниже — запуск на Windows без Docker.
>
> **Официальный API ВК.** Если задан сервисный ключ приложения ВК (`--vk-token` или переменная `VK_PARSER_VK_TOKEN`), `collect` и `watch` читают стену методом `wall.get` вместо браузера (модуль `vk_api.py`). Формат постов, архив, очередь и публикация — те же. Это нужно на сервере: с адресов дата-центров ВК не пускает программный браузер.

По умолчанию настроен адрес **https://vk.ru/cvetyurala**. При запуске без аргументов появляется меню: можно выбрать количество постов, собрать их один раз, постоянно следить за новыми публикациями или подключить свой Telegram-канал. Тексты, ссылки, фотографии и доступные видео сохраняются на диск.

## Быстрый запуск в Windows PowerShell

Нужны Python 3.10+ и Chrome. Распакуйте весь архив и откройте терминал в папке с `vk_parser.py`. Установка зависимостей:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe vk_parser.py
```

При последующих запусках достаточно последней команды. Активировать виртуальное окружение не требуется.

Меню:

```text
1. Собрать последние посты
2. Постоянно следить за новыми постами
3. Подключить Telegram-канал
4. Проверить сохранённые файлы
0. Выход
```

В пункте **1** нажмите Enter для адреса cvetyurala и введите нужное количество постов. Результат появится в `runs/<дата_время>/`, включая `manifest.json` и `preview.html`. Если в сообществе меньше постов, будет сохранено доступное количество.

## Подключение своего Telegram-канала

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username бота. Сохраните выданный токен. [Создание бота](https://core.telegram.org/bots/features#creating-a-new-bot).
2. Добавьте этого бота в свой канал администратором и включите право публикации сообщений. [Права администратора канала](https://core.telegram.org/bots/api#chatmemberadministrator).
3. Запустите `vk_parser.py` и выберите пункт **3**. Введите токен в скрытом поле терминала, затем `@username` канала либо его числовой ID.
4. Для частного канала можно ввести `find`: опубликуйте любой пост в своём канале, где бот уже администратор, затем нажмите Enter. Программа покажет доступные каналы из обновлений бота.
5. Программа проверит бота, канал и право публикации и сохранит числовой ID получателя. Настройка сама по себе ничего в канал не публикует.

На Windows токен защищён DPAPI для текущего пользователя и хранится в локальном `settings.json`. В чат токен присылать не нужно. Файл настроек не входит в распространяемый архив. После переноса программы на другой компьютер подключите бота заново. На других ОС используется переменная `TELEGRAM_BOT_TOKEN`.

Отдельная команда подключения:

```powershell
.\.venv\Scripts\python.exe vk_parser.py telegram-setup
```

## Постоянный режим

Выберите пункт **2**, укажите начальное количество постов и интервал проверки, например **60 секунд**. Ответьте «да», если нужно автоматически публиковать новые посты в подключённый канал. Ещё один вопрос позволяет явно разрешить отправку начальной выборки при первом запуске; по умолчанию она только сохраняется в архив.

Скрипт работает, пока запущен Python, компьютер включён и доступен интернет. Остановка — **Ctrl+C**. После нового запуска с той же папкой архива состояние восстанавливается. Для работы круглосуточно нужен постоянно включённый компьютер или сервер; выключение ПК останавливает проверки.

Команда без меню, после подключения канала:

```powershell
.\.venv\Scripts\python.exe vk_parser.py watch --limit 10 --interval 60 --telegram --headless
```

Без `--telegram` новые публикации только сохраняются. `--publish-existing` дополнительно разрешает отправить начальную выборку **при первой инициализации** этой стены в архиве. Повторный запуск с этим флагом не превращает ранее сохранённую историю в новую очередь.

Наблюдение хранит:

- `archive/watch.sqlite3` — известные ID, очередь сохранения и состояние публикации;
- `archive/items/<owner_id>_<post_id>/` — данные, HTML, фото и MP4 каждого поста;
- `archive/manifest.json` и `archive/preview.html` — общий архив сохранённых публикаций;
- `archive/watch.log` — журнал работы с ротацией;
- `archive/last_scan.json` — итог последнего успешного просмотра.

Вложения известных сохранённых постов не скачиваются заново. Если новых постов оказалось больше начального лимита, окно просмотра расширяется до пересечения с прошлым состоянием. Если пересечение не найдено в пределах `--max-catchup` (по умолчанию 1000), состояние не продвигается: нужно увеличить предел. Это предотвращает тихий пропуск большого количества публикаций между проверками.

Сетевые сбои приводят к повторной проверке с увеличенной паузой до пяти минут. Незавершённые фото остаются в очереди. При неопределённом результате Telegram повторная отправка этого поста блокируется до ручной сверки; сбор новых постов продолжается. Автоматическая очередь сохраняет порядок: если в ней застрял более ранний пост, последующие ждут. Ручная сверка описана ниже. Одновременно запускать два наблюдения для одной папки архива нельзя — второй процесс получит сообщение о занятой папке.

Для проверки двух циклов без Telegram:

```powershell
.\.venv\Scripts\python.exe vk_parser.py watch --limit 2 --interval 15 --cycles 2 --output watch-test --headless
.\.venv\Scripts\python.exe vk_parser.py verify watch-test
```

Для **cvetyurala** плашка «Войдите ВКонтакте, чтобы смотреть посты» закрывается автоматически её собственным крестиком, в том числе при повторном появлении. Она распознаётся по заголовку и кнопке закрытия внутри конкретного окна.

Без ручного взаимодействия:

```powershell
.\.venv\Scripts\python.exe vk_parser.py collect --headless --output run-headless
```

Если вместо этой закрываемой плашки сайт потребует обязательный вход, капчу или сообщит об ограничении доступа, сбор останавливается, сохраняет полученные данные и возвращает код 2. Для ручного действия запустите `collect --manual --profile .vk-profile --output run-manual`, выполните действие в браузере и нажмите Enter в терминале. Пароль скрипт не запрашивает. Отдельный профиль `.vk-profile` сохраняет сессию для следующих запусков. Для повторного сбора используйте новую папку `--output`; существующие результаты не перезаписываются.

Selenium Manager подбирает драйвер при первом запуске. Если доступа к загрузке драйвера нет, передайте `--driver C:\путь\chromedriver.exe`; нестандартный Chrome задаётся через `--chrome`. Кэш драйвера по умолчанию находится в `.selenium-cache` относительно текущей папки. [Документация Selenium Manager](https://www.selenium.dev/documentation/selenium_manager/).

## Результат сбора

В папке `run`:

- `manifest.json` — выбранные публикации, точные даты UTC, текст, ссылки с подписями, фотографии, видео, статусы и причины неполноты;
- `posts.csv` — краткая таблица выбранных постов в UTF-8 с BOM;
- `posts/<owner_id>_<post_id>.json` — все обнаруженные кандидаты;
- `media/<owner_id>_<post_id>/` — скачанные вложения и их SHA-256 в JSON;
- `snapshots/` — HTML конкретных постов;
- `diagnostics/` — HTML текущего DOM и скриншоты страницы;
- `preview.html` — локальный предпросмотр текста и фотографий.

Текст, JSON и HTML всегда связываются по паре `owner_id + post_id`. Посты другого владельца и вложенные репосты не попадают в список кандидатов стены. Комментарии исключаются из разбора содержимого поста.

Ожидание проверяет пост с ID и текстом либо вложением. Во время прокрутки DOM отслеживается через `MutationObserver`; снятые блоки сохраняются даже после их удаления из страницы. Встроенный JSON и JSON-ответы, которые **сам сайт уже загрузил в браузере**, дополняют DOM. Скрипт не выполняет отдельные запросы к внутренним методам API ВК. Для синхронизации используются явные ожидания Selenium. [Waiting Strategies](https://www.selenium.dev/documentation/webdriver/waits/).

Для выбора просматриваются дополнительные кандидаты за пределами первых десяти, затем удаляются дубли и выполняется сортировка по времени. Закрепление не меняет порядок. Это выборка из доступной и просмотренной части стены: изменённая сортировка самой страницы, пропуски доступа или смена разметки требуют проверки `manifest.selection`. Скрипт не утверждает, что просмотрел всю стену.

## Полнота данных и медиа

`complete` означает, что поддерживаемые поля извлечены, JSON и DOM нужного поста найдены, машинная дата известна, фотографии скачаны и нет обнаруженных расхождений. Это результат проверки известных схем, а не гарантия распознавания любой будущей разметки ВК. `partial` и `unavailable` сопровождаются списком `issues`.

Ссылки хранятся как `{"text": "Наш магазин", "url": "https://…"}`. Абзацы, `<br>` и эмодзи сохраняются; исходный JSON-текст остаётся в `raw_text`. Разные версии текста из JSON и DOM отмечаются как расхождение, а DOM-текст сохраняется отдельно.

Фотографии берутся из вложений, без аватаров, иконок и видеопревью. `quality=original_from_metadata` используется только для URL из `orig_photo`; `largest_available` означает наибольший явно переданный размер; `dom_resolution_unverified` — разрешение по одному DOM не подтверждено. Адреса размеров не конструируются заменой параметров в URL. HTML сам по себе медиа не скачивает.

Видео по умолчанию скачиваются через `yt-dlp` из доступного источника; для обработки видео используется поставляемый с `imageio-ffmpeg` FFmpeg. Название, описание и ссылка на видео сохраняются всегда. Если источник недоступен, остаются метаданные и ссылка, `download_status=link_only` и причина в `download_error`; консоль сообщает об этом. Присутствие плеера не подменяет проверку наличия файла. `--video-links-only` отключает скачивание видео. Защищённый DRM-контент не скачивается. [Документация yt-dlp](https://github.com/yt-dlp/yt-dlp#embedding-yt-dlp).

Доступный MP4 до 50 МБ отправляется через `sendVideo`, чтобы отображаться видео в Telegram. Название клипа и служебная ссылка вида `https://vk.ru/video...` автоматически в текст публикации не добавляются; описание видео сохраняется. Если сохранённый видеофайл больше лимита Bot API, сам файл и метаданные остаются в архиве. Репосты и неподдерживаемые типы вложений помечаются для ручной проверки.

Проверка результата одной командой:

```powershell
.\.venv\Scripts\python.exe vk_parser.py verify run
```

Команда проверяет статусы, даты, отсутствие дублей, наличие файлов и совпадение SHA-256. `ok: true` означает, что обнаруженных ошибок нет; `video_files` показывает число скачанных видео, `video_links_only` — число видео, для которых сохранена только ссылка. Такой же пункт есть в меню.

`selectors.json` содержит селекторы, проверенные на странице cvetyurala 3 ноября 2026 года. В `optional_banners` настроена закрываемая плашка приглашения ко входу: проверяются контейнер диалога, текст заголовка и его собственный крестик. Проверка выполняется при загрузке, прокрутке и раскрытии текста, поэтому повторное появление плашки обрабатывается автоматически. Для других известных необязательных плашек добавьте точные правила после просмотра их HTML. Окна обязательного входа и капчи требуют ручного действия.

## Предпросмотр и подтверждение отправки

Задайте получателя и получите код подтверждения:

```powershell
$env:TELEGRAM_CHAT_ID = '-1001234567890'
.\.venv\Scripts\python.exe vk_parser.py preview run --chat-id $env:TELEGRAM_CHAT_ID
```

Откройте `run/preview.html`, проверьте порядок, текст, медиа и статусы. Затем задайте токен своего бота и вставьте **полный** SHA-256 из предпросмотра:

```powershell
$env:TELEGRAM_BOT_TOKEN = '123456:ВАШ_ТОКЕН'
.\.venv\Scripts\python.exe vk_parser.py send run --chat-id $env:TELEGRAM_CHAT_ID --confirm 'SHA256_ИЗ_PREVIEW'
```

`send` без `--confirm` только создаёт предпросмотр. Код привязан к содержимому, контрольным суммам файлов и получателю. После изменений нужен новый предпросмотр.

Бот должен иметь право публиковать в выбранном канале. Фото и скачанные MP4 одного поста собираются в альбом через `sendMediaGroup`; текст прикрепляется подписью к первому элементу альбома. Одиночное фото или видео тоже получает подпись. Служебные строки «Источник», «Опубликовано», «Видео: Клип …» и автоматически добавленная ссылка на клип в публикацию не добавляются. Текст сохраняет ссылки из самого поста и заканчивается подписью из `post_footer.txt`. По умолчанию:

```text
бот для заказов тг: @flowerfromuralbot
```

Чтобы изменить подпись, откройте **`post_footer.txt` рядом с `vk_parser.py`** в Блокноте. Меняйте текст прямо в файле; Enter добавляет следующую строку. Например:

```text
бот для заказов тг: @flowerfromuralbot
Доставка по городу
Здесь ваша дополнительная строка
```

Сохраните файл в UTF-8. Изменения читаются перед следующей публикацией; для изменения только этого файла перезапуск не требуется. Каждая строка файла появляется отдельной строкой внизу поста. Изменения относятся к следующим публикациям. Если файл отсутствует, используется подпись по умолчанию; пустой файл отключает добавление подписи.

В одном альбоме до 10 вложений; дополнительные вложения образуют следующие группы. Подпись ограничена 1024 символами Telegram: длинный текст без обрезки продолжается следующими сообщениями. Каждая часть получает подпись бота в конце. [Отправка альбомов и ограничения подписей](https://core.telegram.org/bots/api#sendmediagroup).

`sendPhoto` может менять качество изображения в Telegram; скачанный файл остаётся в локальном архиве. Большие фотографии и прочие файлы отправляются через `sendDocument`. Между запросами установлена пауза 3,1 секунды; ошибки 429 приводят к остановке, без автоматического повтора. [Telegram Bot API](https://core.telegram.org/bots/api), [ограничения отправки](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this).

Для обновления остановите текущий процесс, замените файлы кода из нового архива и запустите программу снова. Сохраните `settings.json`, папку `archive`, `delivery.sqlite3` и свою изменённую подпись `post_footer.txt`. Завершённые отправки предыдущего формата распознаются по журналу и повторно альбомом не публикуются. Незавершённая отправка старого формата требует ручной сверки.

Неполные публикации по умолчанию не отправляются. Для осознанно проверенных `partial` можно использовать `--allow-partial` **и в preview, и в send**. Этот флаг не разрешает отправлять выборку с `selection.valid=false` и не разрешает пропускать отсутствующие файлы фотографий.

## Журнал SQLite и неопределённые результаты

Общий `delivery.sqlite3` по умолчанию расположен **рядом с vk_parser.py**, поэтому используется и для следующего сбора в другую папку. Сохраняйте этот журнал и используйте одинаковый вид `chat_id`. Свой постоянный путь задаётся параметром `--db` у `send`, `journal` и `resolve`.

До каждого запроса фиксируется `inflight`; после подтверждённого ответа сохраняются `sent`, первый `message_id` и список всех `message_ids`. Для альбома должны быть подтверждены ID каждого входящего сообщения. Подтверждённые операции пропускаются при повторном запуске. Таймаут, обрыв соединения, HTTP 5xx, неполный ответ об альбоме и неразборчивый ответ дают `unknown`. При аварийном завершении может остаться `inflight` — его нужно считать неопределённым. Статусы `unknown`, `inflight` и `failed` блокируют повторную отправку этого поста и любой подборки, которая его содержит, до ручной сверки; отдельные новые посты могут публиковаться. Токен бота в журнал не записывается.

```powershell
.\.venv\Scripts\python.exe vk_parser.py journal
```

Перед ручным исправлением **остановите все процессы send**. Если сообщение найдено в Telegram, укажите его фактический ID и значения из `journal`:

```powershell
.\.venv\Scripts\python.exe vk_parser.py resolve --destination '123456:-1001234567890' --post=-236279991_376 --operation 'text:0' --action sent --message-id 42 --note 'Сообщение найдено в канале и сверено'
```

Для альбома укажите его ключ операции из `journal` и **все** фактические ID через `--message-ids 101,102,103,104`. Одного ID для подтверждения всего альбома недостаточно.

Если после проверки решили повторить запрос, используйте `--action retry --note 'Причина решения после ручной проверки'`. Такая команда только разрешает повтор; сама ничего не отправляет. Затем снова выполните `send` с подтверждением. У Bot API здесь нет клиентского ключа идемпотентности: при потере ответа невозможно гарантировать отсутствие дублей без ручной сверки.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Локальные браузерные проверки дополнительно включаются указанием установленного драйвера:

```powershell
$env:VK_TEST_DRIVER = 'C:\путь\chromedriver.exe'
```
